# Karpathy 编码行为准则

结合项目规则使用。按风险决定流程深度，简单任务不机械套用。

## 1. 编码前先思考

- 读取相关规则、代码和测试。明确目标和验收标准。
- 说明关键假设和取舍。低风险细节可以说明可逆假设后继续。
- 未决事项影响正确性、范围、兼容性或授权时再问，同时推进独立工作。

## 2. 简单优先

- 先跑通最小端到端路径。不加未要求的功能和预防性抽象。
- 先查平台能力、现有代码和依赖。遇到不熟悉且影响大的设计，再比较经验证的做法。
- 遵循领域边界、代码分层和依赖方向。保留安全、可靠性和可测试性。临时方案要有退出条件。

## 3. 精准修改

- 保留已有改动、公开契约和范围外行为。沿用项目风格。
- 只清理本次改动造成的残留。无关问题可以指出，不顺手修复。
- 解释、审阅和排查保持只读。发布、付费、难以恢复等不在已有授权内的操作，先确认。

## 4. 目标驱动的执行

- 定义怎样算通过或失败。修复前先复现问题或取得根因证据。
- 运行项目要求的检查，用实际行为逐项核对验收标准。改动跨边界时扩大验证范围。
- 说明改了什么、哪些检查通过、哪些还没验证。只有更易理解时才用图或交互演示，演示不代替验证。
